Genie to Streamlit

One serving endpoint sits between the agents you configure and the chat UI your users see. Everything below hangs off that seam.

The whole path

Two things happen at different times and people conflate them. Configuring Genie and the supervisor is build time, done once in the UI. Answering a question is run time, and it travels a different route through the same objects.

One question, end to end

What the accent path in the diagram actually executes.

  1. User types into st.chat_input()Streamlit appends the turn to st.session_state.messages and reruns the script.
  2. The app builds a fresh clientIn Databricks Apps, from st.context.headers["X-Forwarded-Access-Token"]. Rebuilt every turn — that token expires and goes stale across WebSocket reconnects.
  3. It calls the Responses APIclient.responses.create(model=ENDPOINT, input=history, stream=True). Not chat completions: the endpoint's task type is Agent (Responses).
  4. The supervisor picks a subagentRouting is driven by the tool descriptions you wrote at build time, filtered by what the caller can access. No access to any subagent ends the conversation; partial access silently reroutes.
  5. Genie turns the question into SQLIt runs against the SQL warehouse, reading the Unity Catalog tables the caller has SELECT on.
  6. Results stream back as eventsresponse.output_text.delta carries prose; response.output_item.done carries the tool call and its output — the generated SQL and the result rows.
  7. Streamlit renders the three shapesProse to st.markdown, SQL to st.code, rows to st.dataframe. Genie does not return charts over the API, so plot them yourself.
